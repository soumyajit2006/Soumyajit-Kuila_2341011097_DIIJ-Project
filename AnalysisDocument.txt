Transaction boundaries ensure database consistency by treating multiple SQL operations as a single atomic unit. If any operation fails during execution, rollback restores the database to its previous consistent state and prevents partial updates.

PreparedStatement improves performance because SQL queries are precompiled and execution plans are reused. It also prevents SQL injection attacks and improves query safety.

Batch processing improves throughput because multiple SQL operations are grouped together, reducing communication overhead and commit cost.

Indexes improve query performance by avoiding full-table scans and enabling faster record lookup.

There is a trade-off between safety and speed. Features such as transactions, rollback handling, savepoints, indexing, and prepared statements introduce additional processing overhead, but they significantly improve reliability, consistency, and security of database operations.

The project uses Apache Derby Embedded Mode. Therefore, network disconnect simulations are not applicable. However, transaction conflicts and rollback scenarios were successfully validated using Derby lock conflicts and forced transaction failures.
